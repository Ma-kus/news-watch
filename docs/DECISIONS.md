# 設計決策紀錄 (ADR)

## ADR-001 靜態 SPA + Python 收集器
- 狀態:接受 (v1.0.0)
- 背景:需每日更新的網頁 App,單人使用。
- 決策:純靜態前端(無框架)+ 標準函式庫 Python 收集器 + JSON 檔資料。
- 後果:部署簡單、無後端;無法在網站端寫入資料。

## ADR-002 新聞來源採 Google News RSS
- 狀態:接受 (v1.0.0)
- 決策:無需 API 金鑰,支援中英文與時間範圍查詢。
- 後果:連結為 Google News 轉址;依標題/來源,非全文。

## ADR-003 公開通道(tunnel)方案 — 否決
- 狀態:**否決** (v1.0.0)
- 背景:使用者要從自己的瀏覽器開啟本機 8080 的網站。
- 嘗試:以臨時通道公開。
- 結果:執行環境對外網路限制嚴格,所有通道無法連線。且臨時網址會變動、知道網址者皆可看。
- 決策:改為部署到固定網站空間。

## ADR-004 部署到 GitHub Pages
- 狀態:接受 (v1.0.0)
- 背景:候選為 GitHub Pages / Netlify / Cloudflare Pages;使用者已有 GitHub 帳號。
- 決策:repo `Ma-kus/news-watch`,Pages 由 `main` 根目錄提供,`deploy.sh` 推送;以 device flow 授權 gh CLI(不儲存 token 於 repo)。
- 後果:網址固定(<https://ma-kus.github.io/news-watch/>);免費帳號內容公開;**根目錄檔案不可隨意搬移**。

## ADR-005 設定存 localStorage,由使用者貼給助理
- 狀態:接受 (v1.0.0→v2.0.0)
- 背景:Pages 靜態,`server.py` 的儲存 API 在公開站被停用(403)。
- 決策:設定面板存瀏覽器;使用者複製 JSON 給助理,助理覆寫 `config/preferences.json` 於隔天生效。
- 後果:設定不跨裝置;需人工貼上。

## ADR-006 重新設計為編輯簡報 + AI 策展
- 狀態:接受 (v2.0.0)
- 背景:687 則新聞太多,使用者要的是「對工作有用」的 20 則。
- 決策:腳本只產候選(計分),由 AI 助理依四大視角選稿、翻譯、撰寫分析。
- 後果:品質依賴助理判斷;以 `validate_brief.py` 與 URL 白名單控管,杜絕捏造連結。

## ADR-007 條件採三層 + 意外重要名額
- 狀態:接受 (v2.0.0)
- 背景:使用者不希望被關鍵字限制而漏掉重要新聞。
- 決策:(1) 四視角開關與權重;(2) 關注公司清單;(3) 關鍵字僅加分、排除詞獨立;另有台灣/全球比重、當日額外關注、W 名額(預設 3)。
- 被否決:關鍵字作為硬性門檻。

## ADR-008 保留全部新聞於每日 pool
- 狀態:接受 (v2.0.0)
- 決策:每日 `pool-DATE.json` 永久累積,前端提供「全部新聞」搜尋/篩選。
- 後果:repo 隨時間增長,未來可評估壓縮或分年封存。

## ADR-009 雙視角分析
- 狀態:接受 (v2.1.0)
- 決策:`analysis_editor` 與 `analysis_executive` 同時產出,UI 可切換/並排,`#n` 引用;舊版 `analysis` 改為選填。
- 後果:舊 brief 仍可顯示(向下相容)。

- 背景:早期無版本標籤,git 歷史僅為部署自動提交。
